<h2>13.1 线程与线程组</h2>

<p>GPU 擅长大规模并行。计算着色器把工作切成<b>线程组</b>（thread group），每个组里有固定数量的线程，一次 <code>Dispatch</code> 启动一批组。</p>

<Callout tone="note">
  <b>组内线程数上限</b>
  <p>一个线程组的总线程数（X·Y·Z）不能超过 1024（多数硬件）。常用的形状是 256 个线程的一维组，或者 8×8、16×16 的二维组。</p>
</Callout>

<h2>13.2 一个简单的计算着色器</h2>

<CodeSample
  title="最小可运行的计算着色器"
  language="hlsl"
  code={`Texture2D      gInput  : register(t0);
RWTexture2D<float4> gOutput : register(u0);

[numthreads(16, 16, 1)]
void CS(uint3 dispatchThreadID : SV_DispatchThreadID)
{
    uint width, height;
    gOutput.GetDimensions(width, height);
    if (dispatchThreadID.x >= width || dispatchThreadID.y >= height)
        return; // Dispatch 按线程组向上取整时，边缘组可能超出纹理尺寸

    // 简单地把输入复制（并做一个反色）到输出
    float4 c = gInput[dispatchThreadID.xy];
    gOutput[dispatchThreadID.xy] = float4(1.0f - c.rgb, 1.0f);
}`}
  input={<>一张输入纹理（SRV，t0）与一张输出纹理（UAV，u0）。</>}
  keyLines={[
    { code: '[numthreads(16, 16, 1)]', note: '声明组内线程数；总数不能超过硬件上限（通常 1024）。' },
    { code: 'RWTexture2D<float4>', note: '可读写资源，必须绑成 UAV；读用普通 Texture2D 绑 SRV。' },
    { code: 'SV_DispatchThreadID', note: '全局线程 ID，直接当作像素坐标使用最方便。' },
    { code: 'if (dispatchThreadID.x >= width || dispatchThreadID.y >= height)', note: 'Dispatch 通常按线程组向上取整，最后一组可能覆盖到纹理外；必须先检查边界。' },
  ]}
  output={<>输出纹理里是反色后的图像；图 13.9 对比了模糊前后的效果。</>}

    '忘记把输出资源设成 UAV：编译或绑定报错。',
    'Dispatch 使用向上取整的组数却没有尺寸检查：边缘线程会读写纹理范围之外。',
    '读写之间没有同步：同组内线程互相依赖时必须用 GroupMemoryBarrierWithGroupSync()。',

<section className="lesson-section" id="s133">
<h2>13.3 数据输入输出资源</h2>

<p>计算着色器读 <b>SRV</b>（<code>Texture2D</code>、<code>StructuredBuffer</code>），写 <b>UAV</b>（<code>RWTexture2D</code>、<code>RWStructuredBuffer</code>）。UAV 在创建和绑定时都要指定正确的资源状态（<code>D3D12_RESOURCE_STATE_UNORDERED_ACCESS</code>）。</p>

<Callout tone="warning">
  <b>UAV 与渲染目标不能同时绑</b>
  <p>同一资源在同一时刻不能既是 UAV 又是渲染目标。做后处理时要先把后台缓冲复制/渲染到离屏纹理，再用计算着色器处理（图 13.7 的 render-to-texture 就是这一类）。</p>
</Callout>
</section>

<section className="lesson-section" id="s135">
<h2>13.5 Append 与 Consume 缓冲</h2>

<p><code>AppendStructuredBuffer</code> 与 <code>ConsumeStructuredBuffer</code> 提供一个无锁的「多写一读」队列：多个线程可以往里追加元素，另一趟 Pass 再消费它们。粒子系统常用它来做「存活粒子列表」。</p>

<Callout tone="tip">
  <b>计数是隐式的</b>
  <p>Append/Consume 的计数器由硬件维护，不需要你自己做原子加。但缓冲区容量要预留够，溢出的元素会被丢弃（不报错）。</p>
</Callout>
</section>

<section className="lesson-section" id="s136">
<h2>13.6 共享内存与同步</h2>

<p>每个线程组有一块 <code>groupshared</code> 内存，访问速度远高于全局显存。典型用法是「先把一块数据搬进共享内存 → 同步 → 再各自计算」。</p>

<Callout tone="warning">
  <b>必须同步</b>
  <p>写共享内存之后、读之前，必须调用 <code>GroupMemoryBarrierWithGroupSync()</code>。少了它，线程可能读到别的线程还没写完的旧值——这类 bug 表现随机，极难定位。</p>
</Callout>
</section>

<h2>本章小结</h2>

<ul>
  <li>计算着色器不在渲染管线内，独立读写 GPU 资源；工作单位是线程组，一次 Dispatch 启动一批组。</li>
  <li>组内线程总数通常不超过 1024；<code>[numthreads]</code> 声明组形状。</li>
  <li>四种 ID：GroupID、GroupThreadID、DispatchThreadID（= GroupID × GroupSize + GroupThreadID）与 GroupIndex。</li>
  <li>读用 SRV、写用 UAV；UAV 与渲染目标不能同时绑在同一资源上。</li>
  <li>共享内存 + <code>GroupMemoryBarrierWithGroupSync()</code> 是减少重复读取的核心手段。</li>
  <li>模糊用分离的两趟一维核；组边界要填 halo，图像边界要 clamp。</li>
</ul>
