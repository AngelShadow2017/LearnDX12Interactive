本章学习目标（Objectives）

  • 学会向量在几何上和数值上如何表示；
  • 掌握向量的各种运算及其几何意义；
  • 熟悉 DirectXMath 库中的向量类型与函数。

向量（vector）是同时具有大小和方向的量。力（某方向上用多大力）、位移（朝哪移动、移多远）、速度（多快、朝哪）都是向量。在 3D 游戏里，向量几乎无处不在：表示玩家视线方向、多边形朝向、光线传播方向……本章是全书的地基。

1.1 向量

几何表示

几何上，向量是一根有方向的线段：线段的长度是大小，箭头指向是方向。书中用"指挥蚂蚁向北爬 10 米"的例子说明：只告诉你方向和距离，不告诉你起点——这正是向量的特性，它只描述"怎么动"，不描述"在哪"。

数值表示：坐标系

计算机无法直接处理"几何线段"，所以要引入坐标系把向量数字化。做法是：平移向量使其尾部对齐坐标原点，此时向量头部的坐标就是它的数值表示。这样向量 v = (x, y, z) 就成了三个数的数组。

左手系与右手系

同样是 x 轴向右、y 轴向上，z 轴指向哪决定了系统的"手性"：

  • 左手系（Left-Handed）：z 轴指向屏幕里（远离观察者）。Direct3D 使用左手系，+x 向右、+y 向上、+z 指向屏幕内部。
  • 右手系（Right-Handed）：z 轴指向屏幕外（朝向观察者）。OpenGL 和许多数学教材使用右手系。
⚠️ 新手大坑：同一个向量 v = (2, 2, 1) 在左手系和右手系中描述的是"不同的位置方向"。看别人的代码或图形 API 文档时，第一件事就是确认坐标系手性，否则物体方向会左右颠倒。

基本运算

  • 相等：对应分量都相等。
  • 标量乘法 k·u：每个分量乘 k。k > 0 方向不变长度缩放；k < 0 方向反转；几何上相当于把向量拉长/缩短 k 倍。
  • 加法 u + v：对应分量相加。几何上把 v 的尾部接到 u 的头部（三角形法则）。物理例子：球上多个力用向量加法合成合力。
  • 减法 u − v：等价于 u + (−v)。

这些运算都满足交换律、结合律等标准性质，书中逐条给出证明，重点是记住几何意义。

1.2 长度与单位向量

向量的长度（模，magnitude）记作 ‖u‖，对 3D 向量用两次勾股定理推导：

‖u‖ = √(x² + y² + z²)

单位向量是长度为 1 的向量。把任意向量除以自己的长度即可"归一化"（normalize）：

û = u / ‖u‖

单位向量只保留"方向"信息。很多计算（比如光照里的法线、视线方向）必须先归一化，否则结果会错。零向量无法归一化（除以 0），代码里要防。

1.3 点积（Dot Product）

点积（内积）是向量代数里最重要的运算之一，定义为对应分量乘积之和：

u · v = uxvx + uyvy + uzvz

同时它有一个极其有用的几何关系：

u · v = ‖u‖‖v‖·cosθ  （θ 是两向量的夹角）

由这个公式立刻得到游戏中天天在用的判断：

  • u · v = 0 → 两向量垂直（正交）；
  • u · v > 0 → 夹角小于 90°（方向"大致相同"）；
  • u · v < 0 → 夹角大于 90°（方向"大致相反"）。

典型应用：判断敌人是否在你面前——取你的朝向向量与"到你"的向量做点积，看正负与阈值。

1.3.1 正交化（Orthogonalization）

有时一组向量"接近"正交但差一点（浮点误差累积后常见），需要把它们重新正交化。书中讲经典的 Gram-Schmidt 正交化：以 w₀ 为基准，把 w₁ 中平行于 w₀ 的分量减掉：

w₁′ = w₁ − projw₀(w₁) = w₁ − (w₁·w₀ / ‖w₀‖²)·w₀

3D 里再对第三个向量减去它在两个已正交向量上的投影。DX12 渲染中构造正交基（如相机坐标系、切线空间）全靠这一套。

1.4 叉积（Cross Product）

叉积只对 3D 向量有意义，结果不是数，而是向量：

w = u × v  （w 同时垂直于 u 和 v）

分量公式（可记行列式展开）：

u × v = (uyvz − uzvy,  uzvx − uxvz,  uxvy − uyvx)

长度满足 ‖u × v‖ = ‖u‖‖v‖·sinθ——这正好等于 u、v 张成的平行四边形面积。

📌 方向怎么定：左手系里，伸出左手让四指从 u 转向 v，拇指指向就是 w 的方向；右手系用右手。（书里用"扫把"手势图讲解这一记忆法。）反交换律：u × v = −(v × u)。

1.4.1 伪 2D 叉积

2D 平面里常用"伪叉积"求一个垂直向量：u = (ux, uy, 0) 的正交向量 v = (uy, −ux, 0)，即交换分量并给其中一个变号。

1.4.2 用叉积做正交化

给定两个不共线的向量，直接 w = u × v 得到第三个正交向量，再用 w × u 得到 v——这是构造正交基的另一种方式（第 8 章法线贴图的切线空间就用它）。

1.5 点（Points）

向量表示"位移/方向"，点表示"位置"。我们用相同的三元组 (x, y, z) 存储点，但要区分两者：

  • 位置向量（position vector）：从原点指向该点的向量——用一个向量来描述点的位置。
  • 点 + 向量 = 点：从点 p 出发沿向量 v 移动，得到新点 q = p + v。
  • 点 − 点 = 向量：q − p 是从 p 指向 q 的向量。

数学上用"齐次坐标"区分：点 w 分量 = 1，向量 w 分量 = 0。第 3 章讲仿射变换时会用到这一约定。

1.6 DirectXMath 向量库

DirectXMath（命名空间 DirectX，头文件 #include <DirectXMath.h>，库 DirectXMath.lib）是为 SSE2/SSE4.1 指令集优化的 128 位 SIMD 数学库——一条指令同时对 4 个 float 运算，游戏里成千上万次向量运算因此大幅提速。

核心类型

  • XMVECTOR：128 位主向量类型，映射到 SIMD 硬件寄存器。建议局部变量与计算全程使用。成员（x, y, z, w）通过 X/Y/Z/W 访问（调试时），但直接访问慢。
  • XMFLOAT2 / XMFLOAT3 / XMFLOAT4：普通结构体，用于类的数据成员和存储（如顶点数据），直接运算效率低。
  • 两者之间用加载/存储函数转换：
// 加载：XMFLOAT3 → XMVECTOR
XMVECTOR XM_CALLCONV XMLoadFloat3(const XMFLOAT3* pSource);
// 存储：XMVECTOR → XMFLOAT3
void XM_CALLCONV XMStoreFloat3(XMFLOAT3* pDestination, FXMVECTOR V);

传参规则

函数参数用类型别名区分该用哪种寄存器传：

  • FXMVECTOR —— 第 1–3 个 XMVECTOR 参数
  • GXMVECTOR —— 第 4 个
  • HXMVECTOR —— 第 5、6 个
  • CXMVECTOR —— 第 7 个及以后

函数声明和调用处都要加 XM_CALLCONV 调用约定宏。

常用函数速查

XMVECTOR n = XMVectorSet(1.0f, 0.0f, 0.0f, 0.0f); // 构造向量
XMVectorZero();          // 零向量
XMVectorSplatOne();      // (1,1,1,1)
XMVector3Length(u);      // 长度（结果在返回向量的 x 分量）
XMVector3Normalize(u);   // 归一化
XMVector3Dot(u, v);      // 点积
XMVector3Cross(u, v);    // 叉积
XMVector3AngleBetweenVectors(u, v); // 夹角弧度
XMVector3Orthogonal(v);  // 求正交向量
XMVectorNearEqual(u, v, eps); // 近似相等（浮点比较）
⚡ 性能：返回值是 XMVECTOR 时结果打包在返回向量的各分量里，用 XMVectorGetX() 等取出。标量返回（标量版函数如 XMVector3LengthSq）也有，但书中推荐统一用向量版保持 SIMD 效率。

1.6.9 浮点误差

float 只有约 7 位有效数字，反复运算会累积误差。对策：用 XMVectorNearEqual 之类的容差比较代替 ==；定期把"近似正交"的基重新正交化。

本章小结

  • 向量 = 大小 + 方向；点 = 位置。数值上都是三元组，但语义不同。
  • Direct3D 是左手系：+x 右、+y 上、+z 进屏幕。
  • 基本运算：加/减（分量运算，几何上三角形法则）、标量乘。
  • 点积返回标量：u·v = ‖u‖‖v‖cosθ，用于夹角、正交判断、投影。
  • 叉积返回向量：u×v 垂直于两者，长度 = 平行四边形面积，用于求法线和构造正交基。
  • Gram-Schmidt 正交化能把"近似正交"修正为真正交。
  • DirectXMath：计算用 XMVECTOR，存储用 XMFLOAT3，用 Load/Store 转换；参数按位置用 FXM/GXM/HXM/CXM。
