<section className="lesson-section lesson-section--intro" id="s41">
<h2>4.1 预备知识</h2>

<p>这一章把「初始化 Direct3D」拆成四件事：理解 CPU 与 GPU 怎么协作、把设备与交换链建起来、给动画准备可靠的时间、以及用调试层把错误暴露出来。</p>

<h3>交换链与页翻动</h3>

<p>为了避免在屏幕上看到正在绘制的画面，D3D 用两个缓冲：<b>前台缓冲</b>正在显示，<b>后台缓冲</b>正在被绘制。画完一帧就交换（flip）两者。</p>

<Figure src="images/Fig4-1.jpg" alt="双缓冲页翻动：第 n 帧时缓冲 A 在显示，下一帧渲染到缓冲 B" figureNumber="图 4.1" caption="第 n 帧时：缓冲 A 正在显示，下一帧渲染到缓冲 B（双缓冲页翻动）。" />

<h3>深度缓冲</h3>

<p>深度缓冲为每个像素保存一个深度值，用来决定谁挡住谁。它不是颜色，而是一张「每个像素最近有多远」的表。</p>

<div className="figure-pair">
  <Figure src="images/Fig4-2.jpg" alt="一组相互遮挡的物体" figureNumber="图 4.2" caption="一组相互遮挡的物体——需要深度缓冲决定谁在前。" />
  <Figure src="images/Fig4-3.jpg" alt="视口窗口对应生成的 2D 图像" figureNumber="图 4.3" caption="视口窗口对应生成的 2D 图像（后台缓冲）；三个像素各自对应场景中不同位置。" />
</div>

<h3>多重采样（MSAA）原理</h3>

<p>只用像素中心采样会出现锯齿（楼梯效应）。MSAA 在一个像素内取多个子采样点，再做加权平均，从而平滑边缘。</p>

<div className="figure-pair">
  <Figure src="images/Fig4-4.jpg" alt="上：锯齿；下：MSAA 平滑后的效果" figureNumber="图 4.4" caption="上：锯齿（用像素矩阵表示直线的楼梯效应）；下：MSAA 多重采样平滑后的效果。" />
  <Figure src="images/Fig4-5.jpg" alt="跨越多边形边缘的像素的单采样与多采样对比" figureNumber="图 4.5" caption="跨越多边形边缘的一个像素：(a) 像素中心采样得到的绿色被存入缓冲，(b) 多采样后取加权平均。" />
</div>

<Callout tone="note">
  <b>书中版本 vs 现在</b>
  <p>D3D12 的交换链本身不支持 MSAA（<code>SampleDesc.Count</code> 必须为 1）。需要抗锯齿时，要创建额外的多重采样离屏缓冲，再解析（resolve）到后台缓冲。</p>
</Callout>
</section>

<section className="lesson-section" id="s42">
<h2>4.2 CPU/GPU 交互</h2>

<h3>命令队列与命令列表</h3>

<p>CPU 把命令记录进命令列表，再提交到命令队列；GPU 从队列里取出命令按序执行。命令列表可以复用，但每次复用前要 Reset。</p>

<Figure src="images/Fig4-6.jpg" alt="命令队列：CPU 提交命令列表，GPU 按序执行" figureNumber="图 4.6" caption="命令队列：CPU 提交命令列表，GPU 按序执行。" />

<h3>CPU/GPU 同步</h3>

<p>两边是<b>并行</b>执行的。CPU 提交完不会等 GPU，而是立刻继续跑。于是出现图 4.7 的情况：</p>

<Figure src="images/Fig4-7.jpg" alt="错误示范：GPU 执行命令 C 使用资源 p2 时，CPU 正在更新 R" figureNumber="图 4.7" caption="错误示范：命令 C 使用资源 p2 绘制时，CPU 正在更新 R——数据竞争。" />

<Callout tone="warning">
  <b>这是本章最重要的一个概念</b>
  <p>CPU 在 GPU 还没用完某块资源时改写它，结果是不确定的：可能 tearing、可能闪烁、可能读到半新半旧的数据。靠「多跑几次试试」永远调不出来，必须显式同步。</p>
</Callout>

<p>解决办法是 <b>Fence</b>（图 4.8）：CPU 用 Signal 在命令流里插入一个路标值；GPU 执行到那个位置就把 fence 值写进去；CPU 用 Wait 阻塞等待某个值被达到。</p>

<Figure src="images/Fig4-8.jpg" alt="CPU 调用 Signal 插入路标，GPU 执行到 xgpu 处写入 fence 值" figureNumber="图 4.8" caption="CPU 调用 Signal 插入路标，GPU 执行到 xgpu 处写入 fence 值。" />

<Callout tone="tip">
  <b>实用规则</b>
  <p>不要向前推进得太远。示例框架用 3 个帧资源轮转，CPU 最多领先 GPU 两帧：每帧先 Wait 上一帧的 fence，再更新帧资源，然后提交并 Signal 本帧。</p>
</Callout>

<section className="lesson-section" id="s43">
<h2>4.3 初始化 Direct3D</h2>

<p>初始化的固定顺序大致是：</p>

<div className="step-list">
  <li>打开调试层（<code>D3D12GetDebugInterface</code> → <code>EnableDebugLayer</code>）。</li>
  <li>创建 DXGI 工厂，枚举适配器，用 <code>D3D12CreateDevice</code> 创建设备（功能级别从 11_0 起）。</li>
  <li>创建 Fence，查询描述符各类型的句柄递增大小。</li>
  <li>检查 MSAA 支持，创建命令队列、命令分配器与命令列表。</li>
  <li>创建交换链（<code>SampleDesc.Count</code> = 1），创建 RTV 与 DSV 描述符堆。</li>
  <li>创建深度/模板缓冲与视图，设置视口与剪裁矩形。</li>
</div>

<Callout tone="warning">
  <b>两个 D3D12 特有的硬要求</b>
  <p>① 常量缓冲视图（CBV）的起始地址和 <code>SizeInBytes</code> 按 256 字节对齐，通常因此把每个常量缓冲槽位的步长向上取整；② D3D12 <b>不提供默认视口</b>，必须自己调用 <code>RSSetViewports</code>，否则什么都画不出来。</p>
</Callout>

<Figure src="images/Fig4-9.jpg" alt="通过修改视口把 3D 场景绘制到后台缓冲的子矩形中" figureNumber="图 4.9" caption="通过修改视口，把 3D 场景绘制到后台缓冲的子矩形中。" />

<h3>资源状态必须显式转换</h3>

  <p>D3D12 要求应用确保资源在使用时处于正确状态；某些资源可以发生隐式提升/衰减，但这里的交换链后台缓冲按显式状态流程处理：绘制前屏障到 RENDER_TARGET，绘制后屏障回 PRESENT。</p>

  language="cpp"
  code={`// 1) 后台缓冲：PRESENT -> RENDER_TARGET

    CurrentBackBuffer(),
    D3D12_RESOURCE_STATE_PRESENT,
    D3D12_RESOURCE_STATE_RENDER_TARGET);

// 2) 清除，并设置视口/剪裁矩形（D3D12 没有默认视口）

mCommandList->ClearDepthStencilView(DepthStencilView(),
    D3D12_CLEAR_FLAG_DEPTH | D3D12_CLEAR_FLAG_STENCIL, 1.0f, 0, 0, nullptr);
mCommandList->RSSetViewports(1, &mScreenViewport);
mCommandList->RSSetScissorRects(1, &mScissorRect);

// 3) 绑定 RTV/DSV 并绘制
auto rtv = CurrentBackBufferView();
auto dsv = DepthStencilView();
mCommandList->OMSetRenderTargets(1, &rtv, true, &dsv);
mCommandList->DrawIndexedInstanced(...);

// 4) 后台缓冲：RENDER_TARGET -> PRESENT
auto toPresent = CD3DX12_RESOURCE_BARRIER::Transition(
    CurrentBackBuffer(),
    D3D12_RESOURCE_STATE_RENDER_TARGET,
    D3D12_RESOURCE_STATE_PRESENT);
mCommandList->ResourceBarrier(1, &toPresent);

ThrowIfFailed(mCommandList->Close());
ID3D12CommandList* lists[] = { mCommandList.Get() };
mCommandQueue->ExecuteCommandLists(_countof(lists), lists);
ThrowIfFailed(mSwapChain->Present(0, 0));
mCurrBackBuffer = (mCurrBackBuffer + 1) % SwapChainBufferCount;`}

<h2>4.6 调试 Direct3D 应用</h2>

<p>D3D12 的 <b>调试层</b>（Debug Layer）会检查参数合法性、资源状态和根签名一致性，并把问题打到输出窗口。它是这本书里最省时间的工具——<b>开发的每一天都应该开着它</b>。</p>

<Figure src="images/Fig4-13.jpg" alt="HRESULT 失败时弹出的错误消息框示例" figureNumber="图 4.13" caption="HRESULT 失败时弹出的错误消息框示例。" />

<Callout tone="note">
  <b>怎么读调试层输出</b>
  <p>第一条消息最有价值，后面的往往是连锁反应。先修第一条，再重跑。常见关键词：<code>RESOURCE_BARRIER</code>（状态没转）、<code>ROOT SIGNATURE</code>（根签名与着色器寄存器不匹配）、<code>invalid parameter</code>（多半是某个对象还是 nullptr）。</p>
</Callout>
