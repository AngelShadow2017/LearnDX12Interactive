<section className="lesson-section lesson-section--intro" id="s71">
<h2>7.1 帧资源</h2>

<p>第 4 章的 CPU/GPU 同步问题在这一章落到实处：因为每帧都要更新常量缓冲，而 GPU 可能还在读上一帧的，所以必须为<b>每一帧准备一份独立资源</b>。</p>

<p>一个 <code>FrameResource</code> 通常包含：</p>

<ul>
  <li>一个命令分配器（<code>ID3D12CommandAllocator</code>）——命令列表 Reset 需要它；</li>
  <li>一份常量缓冲上传堆（物体常量、Pass 常量、材质常量）；</li>
  <li>一个 fence 值，记录「GPU 完成到哪一步」。</li>
</ul>

<Callout tone="warning">
  <b>帧资源数量必须大于 CPU 领先帧数</b>
  <p>CPU 领先 k 帧时，它写的是 k 帧之后的缓冲。帧资源数量 ≤ k 时必然与 GPU 正在读的那一块撞车。示例框架用 3 个帧资源、CPU 最多领先 2 帧。</p>
</Callout>

<section className="lesson-section" id="s72">
<h2>7.2 渲染项</h2>

<p>场景里每个物体都需要「用哪个网格、哪个材质、世界矩阵是多少、要更新哪个常量缓冲槽位」。<b>渲染项</b>（RenderItem）把这些打包成一个结构，绘制时遍历即可。</p>

<CodeSample
  title="渲染项的定义"
  language="cpp"
  code={`struct RenderItem
{
    RenderItem() = default;

    // 世界矩阵与它是否发生变化
    XMFLOAT4X4 World = MathHelper::Identity4x4();
    int NumFramesDirty = gNumFrameResources;   // 新建时要给每个帧资源都更新一次

    // 指向共享的网格与材质
    MeshGeometry* Geo = nullptr;
    Material* Mat = nullptr;

    // 图元拓扑与绘制参数
    D3D12_PRIMITIVE_TOPOLOGY PrimitiveType = D3D_PRIMITIVE_TOPOLOGY_TRIANGLELIST;
    UINT IndexCount = 0;
    UINT StartIndexLocation = 0;
    int BaseVertexLocation = 0;

    // 这个物体在物体常量缓冲里的槽位
    UINT ObjCBIndex = -1;
};`}
  input={<>已创建的网格（<code>MeshGeometry</code>）与材质（<code>Material</code>）。</>}
  keyLines={[

    { code: 'MeshGeometry* Geo / Material* Mat', note: '网格与材质是共享资源，渲染项只存指针。' },
    { code: 'ObjCBIndex', note: '该物体在物体常量缓冲数组里的下标，绘制时用它算字节偏移。' },
  ]}

<section className="lesson-section" id="s73">
<h2>7.3 Pass 常量</h2>

<p>不是每个物体都变的东西（视图投影矩阵、相机位置、时间、雾参数）放在 <b>Pass 常量</b>里，每帧只更新一次，所有绘制共用。</p>

<Callout tone="tip">
  <b>三类常量怎么分</b>
  <p><b>物体常量</b>：每个物体一份（世界矩阵、材质索引）；<b>Pass 常量</b>：每帧一份（视图投影、时间、相机位置）；<b>材质常量</b>：每种材质一份（漫反射颜色、粗糙度）。分清楚之后，每帧要上传的数据量最小。</p>
</Callout>
</section>

<section className="lesson-section" id="s76">
<h2>7.6 根签名进阶</h2>

<p>这一节把根签名从「一个 CBV」扩展成多参数版本，并引入<b>描述符表</b>（descriptor table）与根描述符、根常量的区别。</p>

<ul>
  <li><b>根常量</b>（root constant）：把少量 32 位值直接放进根签名参数，不需要描述符堆；每个值占 1 DWORD，适合少量数据，整体仍受 64 DWORD 上限约束。</li>
  <li><b>根描述符</b>（root CBV/SRV/UAV）：直接放一个 GPU 虚拟地址，无需描述符堆，但数量受限。</li>
  <li><b>描述符表</b>：指向描述符堆里的一段连续范围，适合一批纹理/材质（第 15 章动态索引会用到）。</li>
</ul>

<Callout tone="note">
  <b>限制</b>
  <p>根签名总大小上限是 64 个 DWORD。把大量资源塞进根签名会超出限制，也会降低性能；纹理这类成批资源应走描述符表。</p>
</Callout>
</section>

<section className="lesson-section" id="s78">
<h2>本章小结</h2>

<ul>
  <li>帧资源为每帧提供独立的命令分配器与常量缓冲；数量必须大于 CPU 领先帧数。</li>
  <li>渲染项把「网格 + 材质 + 世界矩阵 + 常量槽位」打包，绘制时遍历即可。</li>
  <li>常量分三类：物体常量、Pass 常量、材质常量，分别按物体、按帧、按材质更新。</li>
  <li>程序化网格：格网顶点数 = (m+1)(n+1)，索引数 = m·n·6；圆柱与球用切片/层控制密度。</li>
  <li>多个网格可以放进同一个顶点缓冲，用 <code>Submesh</code> 的起始偏移区分。</li>
  <li>根签名有三种参数形式：根常量、根描述符、描述符表；总大小上限 64 DWORD。</li>
  <li>动态顶点缓冲（波浪）也要按帧资源分开，避免与 GPU 竞争。</li>
</ul>
